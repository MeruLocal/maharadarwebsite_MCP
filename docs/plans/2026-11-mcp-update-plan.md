## 3. Target contract: a public read-only knowledge layer

**Principles (brief section 3).** One source of truth with the website (`tools.ts`, `limits.json`, `locales.ts`, comparisons, the claim register). Only verified-public facts. No account access, no audits run, no customer actions. Every surface states plainly that this is the public information server, not the Business-plan product MCP.

**Tools (2 retrieval + 8 verb-entity), names as in the brief, mapped to PR #1 where one exists.** Each description states what / when / returns / not-for.

| Tool | Maps to (PR #1) | What | Returns | Not for |
|---|---|---|---|---|
| `search_site` (`search`) | `maharadar_search` | Find records by query | ranked records with canonical URL | A user's own account or site |
| `fetch_record` (`fetch`) | new (PR #2 M5) | One record by id from `search_site` | full record | Arbitrary URLs |
| `list_tools` | `maharadar_list_free_tools` | Free tools with status | `tool_record[]` | Running a tool |
| `get_tool` | `maharadar_get_free_tool` / `maharadar_find_free_tool` | One tool: name, purpose, URL by locale, status | `tool_record` | Running a tool |
| `get_plan_limits` | `maharadar_get_plan_limits` | Approved limits only | `plan_limits` or `{status: "not_published"}` | Unapproved numbers, prices |
| `get_market_info` | new | Engines, privacy regime, currency, availability per market; figures with source and `as_of` | `market_search_engine_fact` / `market` | Legal advice |
| `list_guides` / `get_guide` | `maharadar_get_audience_guide`, `maharadar_get_seo_checklist` | Guide titles and canonical URLs per locale | `guide[]` / `guide` | Unlaunched guides |
| `get_trust_facts` | new | Trust statements exactly as published | `trust_fact[]` | Widening a claim |
| `get_comparison` | new (PR #2 M4) | Dated, sourced facts for published comparison pages | `comparison` | Competitor prices, verdicts |
| `get_changelog` | new | Dated shipped and planned items, never mixed | `changelog_entry[]` | Roadmap promises |

`maharadar_about` and `maharadar_get_platform_feature` stay, rewritten to the envelope and to the entity decision.

**Common record envelope (brief section 3):**

```ts
{
  id: string;
  type: RecordType;
  title: string;
  summary: string;
  canonical_url_by_locale: Record<Locale, string>;
  market: "US" | "GB" | "CA" | "AU" | "IN" | "AE" | "DE" | "FR" | "IT" | "JP" | "global";
  status: "available" | "beta" | "integration" | "coming_soon" | "unavailable" | "not_published";
  last_verified: string;
  publication_status: "draft" | "verified_public" | "withdrawn";
  source_url: string;
  as_of?: string;              // required for any figure
  refresh_date?: string;       // required for any regulated figure
  astra_check?: "passed" | "pending";
  source_commit: string;
}
```

**Output schemas.** Every tool declares an `outputSchema`; `structuredContent` validates against it.

## 7. Security and MCP Registry readiness

- **No write or customer-action tools.** No audits, crawls, account access or form submission. Tool runs happen on the website, not through this server.
- All tools keep read-only annotations; no outbound fetches at request time (PR #1 design).
- **MCP Registry listing only after a security review**, plus the brief's other gates: the two-server naming fix (P2), SOC 2 wording fixed on the site, approved limits (P3), and the entity decision (P1). PR #2 M6 and the PR #1 `docs/submission/` packets wait for all of them.
